# 演示用户型图

在「户型解析」页面上传这里的任意一张，即可跑通完整链路：

```
户型图 → 解析（9 间房 / 墙 / 门 / 窗）→ 户型诊断
      → 2D 矢量图 + 物品热区（AC-07 / AC-09）
      → 3D 第一人称漫游（贴地行走，有碰撞）
```

## 这三张是自己生成的，不涉及版权

生成脚本：`scripts/make_demo_floorplans.py`（可重跑，参数全在里面）

**为什么不去网上找**：项目已有一条规矩 —— 有版权的东西不进这个仓库。
网上的户型图几乎都有来源。而且自己画还有一个更实际的好处：
把家具、指北针、彩色填充、水印、图例这些**干扰项全去掉**，
墙线干净、房间是纯矩形，视觉模型的解析成功率比任何真实扫描件都高。

## 按建筑制图画的，有几处是刻意的

- **墙画成双线**（内外墙面两条线），不是一条粗线
- **窗不打断墙**，只在墙带里加两条线；**只有门打断墙**
- 门有门扇和开启弧，外墙厚 0.24m、内墙 0.12m
- 填浅色房间块（帮模型区分房间），但浅到不影响墙线

第二条不是讲究，是实测出来的：初版把窗画成墙上的缺口，结果视觉模型
照实读出「外墙被切成 12 段、不闭合」，**3D 漫游直接降级成自由视角，
第一人称行走根本起不来**。而建筑制图里窗本来就不打断墙。

## 02 那张为什么是"走廊式"

每个房间的门**直接开向走廊**，不串成链。

链式连通（A→B→C）的问题是：模型只要漏检 B→C 那一扇门，C 以及 C 后面
**所有**房间一起变成孤岛 —— 一次漏检损失一大片。实测就是这么翻的车：
漏掉「客厅↔餐厅」一处敞口，可逛面积掉到 49%，第一人称漫游被判定为不可用。

星形连通最坏情况只是"漏一间丢一间"。

用 `03` 与 `02` 各跑过真实解析（2026-09-23）：

            墙闭合 ✓  可建墙 ✓

同一张图连跑多次，结果会因模型输出而略有差异；上面是其中较好的一次。

## 已知的两个不确定点

**① 门检出率不是 100%，结果有波动。** 同一张图，好的时候 9 扇门全中
（可走面积 100%），差的时候漏一两扇（可走面积 46–70%）。
漏掉的那扇门不计入通行图，它背后的房间会在界面上标灰并写明是哪一间。

**② `01`（一室一厅）实测**有一次**走了降级路径**，返回 `degraded_basic`
（只有房间名、没有坐标），因而拿不到 3D 几何。只跑过这一次，
**不能断定它每次都这样** —— 但演示时用 `02` 或 `03` 更稳妥。

> 这两个都是**上游模型输出**的不确定性，不是几何层的问题 ——
> 几何层的判据（墙闭合、门洞切割、门的两侧、连通性、可站立）
> 全部有测试钉着，其中几条是拿真实解析数据做的回归。

## 自己造新的

改 `scripts/make_demo_floorplans.py` 里的 `Plan` 定义即可：

```python
Plan(
    name="04-...",
    size=(宽m, 深m),
    rooms=[("房间名", x, y, 宽, 深), ...],   # 必须**恰好铺满**，不能留缝或重叠
    openings=[Opening("h", 墙的y, 洞中心x, 洞宽, "door"|"window"), ...],
)
```

房间矩形必须铺满整个 `size` 范围 —— 这个约束由脚本里的网格校验保证，
留缝会在图上画出莫名其妙的双线，重叠会让模型看到两条平行墙。

生成后直接用 `logs/` 之外的方式看：图片是普通 PNG，双击即可。
