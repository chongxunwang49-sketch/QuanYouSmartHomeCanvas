# 演示素材

演示（含面试现场）要用的东西都在这个目录下。两个子目录，**一一对应**：

```
演示素材/
├── 户型图/     3 张自绘户型图 —— 演示时上传的就是它们
└── 演示资料/   3 份「屋主户型详情」—— 与上面三张图同名配对，一一对应
```

命名约定就是配对依据：`01-一室一厅-45平.png` ↔ `01-一室一厅-45平.md`。

---

## 演示时怎么用

1. 进「户型解析」，上传 `户型图/` 里的某一张（例如 `02-两室一厅-78平.png`）
2. 等解析跑完（实测 78 秒左右）
3. 右侧的「补充屋主户型详情」卡片点**载入演示样例** ——
   后端按解析出来的总面积，从 `演示资料/` 里挑最接近的那一份填进输入框
4. 点**保存并重新诊断**，五维诊断会带着这份详情重跑一遍

第 3 步为什么必须由人点一下：这份材料在口径上是**屋主自己提供的**，
得由人确认一次才成立，不做成后端偷偷替他填上（见 `routes.py::sample_house_detail`）。

---

## 两份东西为什么要放在两个位置

| 位置 | 谁在用 | 说明 |
|---|---|---|
| `演示素材/演示资料/` | **人**（作者、演示者） | 唯一真源。跟三张户型图并排，谁做演示都找得到 —— 改内容只改这里 |
| `seed_data/demo_house_details/` | **后端** | 运行时真的会读（`routes.py::_demo_house_details`） |

后端不能读 `演示素材/`，原因在部署层：`deploy/Dockerfile` 里是
`COPY seed_data/ /app/seed_data/`，而 `.dockerignore` 明确排除了 `演示素材`
（那里面还有 44 MB 的全友官网版权摄影，没理由进镜像）。

于是同一份内容有两个位置。**改完真源必须同步一次**：

```bash
python scripts/sync_demo_details.py           # 演示素材 → seed_data（单向）
python scripts/sync_demo_details.py --check   # 只比对，不一致退出码非 0
```

同步是**单向**的，而且 `tests/test_demo_assets.py` 每次跑测试都验一次
两边逐字节相同 —— "改了一份忘了另一份"这种不报错的错误，在这里过不去。

改完 `seed_data/` 要让容器也拿到，得重建后端镜像（`seed_data` 是烘进镜像的，
没有 bind mount）：

```bash
docker compose build qy-backend && docker compose up -d qy-backend
```

依赖层是缓存的，实测重建只走 COPY 那几层，几秒钟。

## 图上的面积数字有个口径差，不是错

三张图的标题写的是「建筑面积约 45 / 86 / 98 ㎡」，而图上逐间标注加起来是
46.8 / 92.1 / 98.1 ㎡。**这不是数据打架**，是两种口径：

- 图上逐间标注：按轴线尺寸逐间量、阳台按全面积计入 —— 制图口径
- 产权证建筑面积：按登记规则折算，含公摊

每份详情里都有一段「面积口径说明」把这件事讲清楚，就是为了让诊断不要
把它当成"数据矛盾"报成一个缺口。

其中 02 那张还多一层：标题的「约 86 ㎡」是不含阳台的口径，
图上阳台单独标了 6.0 ㎡，86.1 + 6.0 恰好回到 92.1。

## 实测记录（2026-09-27）

三张图各真跑了一遍 `POST /layout/parse`，原始结果在 `logs/demo-parse/`。

| 图 | 解析出的总面积 | 后端挑中的样例 | 补详情前 | 补详情后 |
|---|---|---|---|---|
| 01 一室一厅 | 46.8 ㎡ | 01（45.2 ㎡）✓ | 5.0 分 / 置信度 0.4 / 缺口 8 | **6.9 分 / 0.85 / 缺口 3** |
| 02 两室一厅 | 92.1 ㎡ | 02（92.4 ㎡）✓ | 5.7 分 / 置信度 0.6 / 缺口 7 | **7.3 分 / 0.90 / 缺口 0** |
| 03 三室两厅 | 98.1 ㎡ | 03（98.4 ㎡）✓ | 7.0 分 / 置信度 0.4 / 缺口 8 | **7.5 分 / 0.86 / 缺口 3** |

三张图都挑中了自己那一份（第二列），这就是"一一对应"的实测。
补完详情后剩下的缺口都是真缺口 —— 主要是"没有房间相对坐标，动线只能推断"
这一类，不是补一份文档能消掉的，所以**没有为了好看把它抹平**。

重新量一遍：

```bash
python scripts/_probe_demo_parse.py            # 三张图各解析一次
python scripts/_probe_demo_diagnosis.py <layout_id> [...]   # 补详情前后的对照
```

> 这两条都要连本机跑着的后端（`http://127.0.0.1/api/v1`），
> 会真的调视觉模型与诊断模型。
